Lección 0 · Antes de escribir SQL

Conocé la base JARDINERÍA

Antes de cualquier consulta tenés que saber qué tablas hay y cómo se conectan. Es el mapa antes de salir a caminar.
Analogía: planillas de Excel conectadas

Cada tabla es una planilla. Cada fila es un registro (un cliente) y cada columna es un dato (su ciudad).

La PK (clave primaria) es el "DNI" de la fila: no se repite nunca. La FK (clave foránea) es una columna que guarda el DNI de una fila de otra tabla. Por ejemplo, el cliente guarda el código de su vendedor. Gracias a eso podemos unir tablas.

Lección 1 · Leer datos

SELECT y FROM

SELECT elige qué columnas ver y FROM de qué tabla. Solo lee: no cambia nada.
SELECTcolumnasFROMtabla;
Analogía

FROM es qué planilla abrís. SELECT es qué columnas dejás visibles: las demás se ocultan.

SELECT nombre, precio_venta
FROM producto;
SELECT * FROM oficina;   -- el * significa "todas las columnas"

Calcular columnas nuevas

En el SELECT podés poner cuentas y funciones, no solo columnas. La base calcula el valor fila por fila.

+ − * /

Cuentas con columnas.

precio_venta * 1.21

AS

Le pone un nombre (alias) a la columna del resultado.

... AS con_iva

ROUND(x, 2)

Redondea a 2 decimales.

ROUND(precio * 1.21, 2)

CONCAT(a, b)

Une textos en una sola columna.

CONCAT(nombre, ' ', apellido1)

UPPER / LOWER

Pasa a mayúsculas / minúsculas.

UPPER(ciudad)

IFNULL(x, y)

Si x es NULL, muestra y.

IFNULL(region, '-')
SELECT nombre,
       precio_venta,
       precio_venta * 1.21           AS con_iva,
       ROUND(precio_venta * 1.21, 2) AS con_iva_redondeado,
       precio_venta - precio_proveedor AS ganancia
FROM producto;
SELECT CONCAT(apellido1, ', ', nombre) AS empleado, email
FROM empleado;

-- AND: de España Y de Madrid
SELECT nombre_cliente, ciudad FROM cliente
WHERE pais = 'Spain' AND ciudad = 'Madrid';
-- IN: pagos con PayPal o con Cheque
SELECT * FROM pago WHERE forma_pago IN ('PayPal', 'Cheque');
-- BETWEEN: incluye el 2000 y el 5000
SELECT * FROM pago WHERE total BETWEEN 2000 AND 5000;
-- LIKE: nombres que empiezan con "Lim"
SELECT nombre FROM producto WHERE nombre LIKE 'Lim%';
-- IS NULL: pedidos sin fecha de entrega
SELECT codigo_pedido, estado, fecha_entrega FROM pedido WHERE fecha_entrega IS NULL;
-- <>: empleados que NO son representantes
SELECT nombre, puesto FROM empleado WHERE puesto <> 'Representante Ventas';
NULL no es cero ni vacío

NULL significa "no hay dato". = NULL nunca da verdadero. Probá las dos y compará:

SELECT COUNT(*) FROM pedido WHERE fecha_entrega = NULL;
SELECT COUNT(*) FROM pedido WHERE fecha_entrega IS NULL;
AND y OR juntos: usá paréntesis

AND se evalúa antes que OR. "Clientes de Madrid con representante 11 o 30":

-- Mal: trae TODOS los del representante 30, de cualquier ciudad
SELECT nombre_cliente, ciudad, codigo_empleado_rep_ventas FROM cliente
WHERE ciudad = 'Madrid' AND codigo_empleado_rep_ventas = 11 OR codigo_empleado_rep_ventas = 30;
SELECT nombre_cliente, ciudad, codigo_empleado_rep_ventas FROM cliente
WHERE ciudad = 'Madrid' AND (codigo_empleado_rep_ventas = 11 OR codigo_empleado_rep_ventas = 30);

-- Recuperatorio, consigna 9: un solo número
SELECT COUNT(*) AS clientes_barcelona FROM cliente WHERE ciudad = 'Barcelona';
-- COUNT(*) cuenta todo; COUNT(columna) no cuenta los NULL
SELECT COUNT(*) AS pedidos, COUNT(fecha_entrega) AS entregados FROM pedido;

FROM pago;

GROUP BY: un resultado por cada grupo

Analogía

Tirás todas las fichas de clientes sobre la mesa, armás una pila por país y contás cuántas fichas tiene cada pila.

-- Recuperatorio, consigna 8: ¿cuántos clientes tiene cada país?
SELECT pais, COUNT(*) AS cantidad
FROM cliente
GROUP BY pais;

FROM pago
GROUP BY forma_pago;
Regla de oro

Toda columna del SELECT que no esté dentro de COUNT/SUM/AVG/MAX/MIN tiene que estar en el GROUP BY. Si no, MySQL 8 da error.

SELECT pais, COUNT(*) FROM cliente;   -- falta GROUP BY pais
Cómo reconocerlo en la consigna

Si dice "cada" o "por" ("cuántos clientes por país", "total de cada cliente"), hace falta GROUP BY.

-- Países con más de 2 clientes
SELECT pais, COUNT(*) AS cantidad
FROM cliente
GROUP BY pais
HAVING COUNT(*) > 2;
-- Los dos juntos: de los clientes españoles (WHERE), ciudades con 3 o más (HAVING)
SELECT ciudad, COUNT(*) AS cantidad
FROM cliente
WHERE pais = 'Spain'
GROUP BY ciudad
HAVING COUNT(*) >= 3
ORDER BY cantidad DESC;

Cálculos con agregación: la facturación del TP7

Base imponible = suma de precio_unidad × cantidad. IVA = 21% de la base. Total = base + IVA.

SELECT SUM(cantidad * precio_unidad)        AS base_imponible,
       SUM(cantidad * precio_unidad) * 0.21 AS iva,
       SUM(cantidad * precio_unidad) * 1.21 AS total
FROM detalle_pedido;
-- Lo mismo por producto, solo los que empiezan con OR y facturaron más de 1000
SELECT codigo_producto, SUM(cantidad * precio_unidad) AS base_imponible
FROM detalle_pedido
WHERE codigo_producto LIKE 'OR%'
GROUP BY codigo_producto
HAVING SUM(cantidad * precio_unidad) > 1000;
Lección 5 · Combinar tablas

JOIN: unir tablas

Los datos están repartidos en varias tablas. El JOIN pega cada fila de una tabla con su pareja en la otra, usando la columna que comparten (FK = PK).
SELECTa.col, b.colFROMtabla1 aINNER|LEFT|RIGHTJOINtabla2 bONa.fk = b.pk;
Analogía

En pago solo está el número de cliente. Para saber su nombre hay que buscar ese número en cliente. El JOIN hace esa búsqueda por vos, fila por fila.

DemoElegí el tipo de JOIN y mirá qué filas sobreviven
INNER JOINSolo filas con pareja en las dos tablas.
LEFT JOINTodo lo de la izquierda; sin pareja → NULL.
RIGHT JOINTodo lo de la derecha; sin pareja → NULL.
LEFT + IS NULLLos de la izquierda que no tienen pareja.

INNER JOIN

-- Cada cliente con el nombre de su representante
SELECT c.nombre_cliente, e.nombre, e.apellido1
FROM cliente c
INNER JOIN empleado e ON c.codigo_empleado_rep_ventas = e.codigo_empleado;
  • c y e son alias: apodos cortos de cada tabla.
  • ON dice qué columnas tienen que coincidir.
  • c.nombre_cliente = la columna nombre_cliente de la tabla c.

LEFT y RIGHT JOIN

-- Todos los clientes; los que no pagaron aparecen con total NULL
SELECT c.nombre_cliente, p.total
FROM cliente c
LEFT JOIN pago p ON c.codigo_cliente = p.codigo_cliente;
-- Clientes que NUNCA pagaron (TP7, punto 16)
SELECT c.nombre_cliente
FROM cliente c
LEFT JOIN pago p ON c.codigo_cliente = p.codigo_cliente
WHERE p.codigo_cliente IS NULL;
-- Lo mismo con RIGHT JOIN: ahora cliente está a la DERECHA
SELECT c.nombre_cliente
FROM pago p
RIGHT JOIN cliente c ON c.codigo_cliente = p.codigo_cliente
WHERE p.codigo_cliente IS NULL;

NATURAL JOIN: une solo por nombres iguales

No lleva ON: une por todas las columnas que se llamen igual en las dos tablas. Entre cliente y pago la única en común es codigo_cliente, así que funciona:

SELECT nombre_cliente, forma_pago, total FROM cliente NATURAL JOIN pago;
-- Clientes sin pagos con NATURAL LEFT JOIN (TP7, 16 c)
SELECT codigo_cliente, nombre_cliente FROM cliente NATURAL LEFT JOIN pago WHERE id_transaccion IS NULL;
Peligro

empleado y cliente no tienen ninguna columna con el mismo nombre (codigo_empleado ≠ codigo_empleado_rep_ventas). El NATURAL JOIN las combina todas con todas: 31 × 36 = 1116 filas sin sentido.

SELECT COUNT(*) FROM empleado NATURAL JOIN cliente;

SELF JOIN: una tabla consigo misma

El jefe de un empleado también está en la tabla empleado. Usás la tabla dos veces con dos alias: e = el empleado, j = su jefe. Es la consigna 7 del recuperatorio.

empleado ee.codigo_jefeempleado j= j.codigo_empleado
SELECT e.nombre AS empleado, j.nombre AS jefe
FROM empleado e
INNER JOIN empleado j ON e.codigo_jefe = j.codigo_empleado;

Se encadenan los JOIN, cada uno con su ON. Seguí el camino de las FK en el diagrama:

-- Cada pago con el cliente, su representante y la ciudad de la oficina (TP7, punto 14)

Columna ambigua

Si una columna existe en las dos tablas (nombre, ciudad, codigo_cliente...), siempre poné el alias delante. Este error estaba en tu parcial (ejercicio 2, punto 5):

SELECT nombre, ciudad FROM empleado e INNER JOIN oficina o ON e.codigo_oficina = o.codigo_oficina WHERE codigo_oficina = 'MAD-ES';

Subconsultas

Cuando para responder algo primero necesitás otro dato de la base. La consulta de adentro se resuelve primero y la de afuera usa su resultado.
SELECTcolumnasFROMtablaWHEREcolumnaIN | = | > ALL(SELECTcolumnaFROMotra);
DemoClientes que hicieron algún pago, paso a paso

Los 4 tipos que pide el TP7

La subconsulta devuelve...UsáEjemplo
Un solo valor= > <el precio máximo, el promedio
Una lista de valoresIN / NOT INlos códigos de los clientes que pagaron
Una lista, comparando con todos o con alguno>= ALL / > ANYmayor o igual que todos = el máximo
Solo importa si hay o no hay filasEXISTS / NOT EXISTS¿este cliente tiene algún pago?
-- = con un valor: productos más caros que el promedio
SELECT nombre, precio_venta FROM producto
WHERE precio_venta > (SELECT AVG(precio_venta) FROM producto);
-- NOT IN con una lista: productos que nunca se pidieron (TP7, 42)
SELECT codigo_producto, nombre FROM producto
WHERE codigo_producto NOT IN (SELECT codigo_producto FROM detalle_pedido);
-- ALL: el cliente con mayor límite de crédito (TP7, 36)
SELECT nombre_cliente, limite_credito FROM cliente
WHERE limite_credito >= ALL (SELECT limite_credito FROM cliente);
-- EXISTS: clientes que tienen algún pago (TP7, 47)
SELECT c.nombre_cliente FROM cliente c
WHERE EXISTS (SELECT 1 FROM pago p WHERE p.codigo_cliente = c.codigo_cliente);

Subconsultas correlacionadas

En el EXISTS de arriba, la subconsulta usa c.codigo_cliente, que viene de afuera. Se re-ejecuta por cada cliente: "¿hay pagos de este cliente?". Así se resuelve el punto 32 del TP7 sin JOIN:

-- Clientes cuyo límite de crédito es mayor que lo que pagaron
SELECT c.nombre_cliente, c.limite_credito
FROM cliente c
WHERE c.limite_credito > (SELECT SUM(p.total) FROM pago p WHERE p.codigo_cliente = c.codigo_cliente);

Subconsultas anidadas: como una cebolla

El punto 44 del TP7 encadena 5 niveles. Se lee de adentro hacia afuera:

5 · oficinas que NO están en...
4 · oficinas de los representantes de...
3 · los clientes de...
2 · los pedidos con...

JOIN o subconsulta

Muchas veces sirven las dos. Si tenés que mostrar columnas de las dos tablas, necesitás JOIN. Si solo filtrás, cualquiera de las dos. Si la consigna dice "sin INNER JOIN" o "con IN/EXISTS", respetalo: el autocorrector lo revisa.

Lección 7 · El patrón que siempre sale

"El que más" y "el que menos"

"El producto con más stock", "el cliente con más pagos"... sale en todos los parciales. Hay dos caminos.

Camino A · ordenar y cortar

Ordenás de mayor a menor y te quedás con el primero.

ORDER BY x DESC LIMIT 1

Camino B · buscar el máximo

Calculás el máximo con una subconsulta y buscás quién lo tiene.

WHERE x = (SELECT MAX(x) ...)
-- A: recuperatorio, consigna 10
SELECT nombre, cantidad_en_stock FROM producto
ORDER BY cantidad_en_stock DESC
LIMIT 1;
-- B: trae TODOS los empatados
SELECT nombre, cantidad_en_stock FROM producto
WHERE cantidad_en_stock = (SELECT MAX(cantidad_en_stock) FROM producto);
Con los datos reales hay empate

35 productos tienen 400 unidades. El camino A muestra uno solo y el B, los 35. El autocorrector acepta los dos, pero B es más preciso.

Cuando primero hay que contar o sumar

1GROUP BY clienteuna pila por cliente
2COUNT(*)cuántos pagos tiene cada pila
3ORDER BY ... DESCde más a menos
4LIMIT 1el primero
-- El cliente con más pagos, mostrando su nombre
SELECT c.nombre_cliente, COUNT(*) AS cantidad_pagos
FROM cliente c
INNER JOIN pago p ON c.codigo_cliente = p.codigo_cliente
GROUP BY c.codigo_cliente, c.nombre_cliente
ORDER BY cantidad_pagos DESC
LIMIT 1;
-- El producto del que más unidades se vendieron (TP7, 31)
SELECT nombre FROM producto
WHERE codigo_producto = (
    SELECT codigo_producto FROM detalle_pedido
    GROUP BY codigo_producto
    ORDER BY SUM(cantidad) DESC
    LIMIT 1
);
Error de tu parcial (ejercicio 2, punto 8)

Se usó ORDER BY count(*) sin GROUP BY. Sin agrupar, COUNT cuenta toda la tabla junta y no por cada consultorio.

Lección 8 · Trabajar con fechas

Fechas en MySQL

Las fechas se escriben 'aaaa-mm-dd' (por ejemplo '2026-10-31') y la de hoy es CURDATE(). '31/10/2026' y GETDATE() no funcionan en MySQL.
FunciónPara qué sirveEjemplo → resultado
CURDATE() / NOW()Hoy / hoy con hora2026-11-15
YEAR(f) MONTH(f) DAY(f)Sacan el año, el mes o el díaYEAR('2008-11-10') → 2008
DATE_FORMAT(f, '%Y')Da formato a la fecha (devuelve texto)'%d/%m/%Y' → 10/11/2008
DATEDIFF(a, b)Días entre dos fechas (a − b)DATEDIFF('2009-01-27','2009-01-25') → 2
ADDDATE(f, INTERVAL n DAY)Suma días (también MONTH, YEAR)ADDDATE('2009-01-25', INTERVAL 2 DAY) → 2009-01-27
TIMESTAMPDIFF(YEAR, a, b)Diferencia en años (edad)mayores de edad: >= 18
VisualDATEDIFF y ADDDATE sobre una línea de tiempo
DATEDIFF = 2 días
2009-01-25fecha_entrega
2009-01-27fecha_esperada

Se entregó 2 días antes: DATEDIFF(fecha_esperada, fecha_entrega) = 2. Visto al revés: ADDDATE(fecha_entrega, INTERVAL 2 DAY) <= fecha_esperada. Las dos formas son el punto 8 del TP7.

-- Clientes con pagos en 2008: tres formas (TP7, punto 6)
SELECT DISTINCT codigo_cliente FROM pago WHERE YEAR(fecha_pago) = 2008;
SELECT DISTINCT codigo_cliente FROM pago WHERE DATE_FORMAT(fecha_pago, '%Y') = '2008';
SELECT DISTINCT codigo_cliente FROM pago WHERE fecha_pago BETWEEN '2008-01-01' AND '2008-12-31';
-- Pedidos entregados tarde y cuántos días de atraso
SELECT codigo_pedido, fecha_esperada, fecha_entrega,
       DATEDIFF(fecha_entrega, fecha_esperada) AS dias_de_atraso
FROM pedido
WHERE fecha_entrega > fecha_esperada;
-- Entregados al menos 2 días antes (TP7, 8 a)
SELECT codigo_pedido, fecha_entrega, fecha_esperada FROM pedido
WHERE ADDDATE(fecha_entrega, INTERVAL 2 DAY) <= fecha_esperada;
-- Formato lindo y cuántos años pasaron
SELECT id_transaccion,
       DATE_FORMAT(fecha_pago, '%d/%m/%Y') AS fecha,
       TIMESTAMPDIFF(YEAR, fecha_pago, CURDATE()) AS anios
FROM pago;
-- Así NO (SQL Server):
SELECT * FROM pago WHERE YEAR(fecha_pago) = YEAR(GETDATE());
"Hoy" cuando la columna tiene hora

Si la columna guarda fecha y hora, col = CURDATE() no coincide nunca. Usá DATE(col) = CURDATE(). Fue el error del ejercicio 2, punto 6 del parcial.

Errores típicos (sacados de tus archivos)

Revisé tu parcial, el archivo de ejemplo de clase y el TP7. Estos son los errores que conviene no repetir. Los de la izquierda se pueden ejecutar para ver el error.

1Falta el FROM

Parcial · ejercicio 1, punto 7
SELECT codigo_pedido, fecha_pedido
ORDER BY fecha_pedido DESC LIMIT 5;
SELECT codigo_pedido, fecha_pedido
FROM pedido
ORDER BY fecha_pedido DESC LIMIT 5;

2Falta una coma: la columna se vuelve alias

Parcial · ejercicio 2, punto 1
SELECT nombre, extension email FROM empleado;
SELECT nombre, extension, email FROM empleado;

No da error, pero email pasa a ser el nombre de la columna extension y el email no se muestra. Ejecutalo y mirá el encabezado.

3Coma antes del AS

ejemplo_20261005.sql (clase)
SELECT CONCAT(apellido1, nombre), AS empleado
FROM empleado ORDER BY empleado;
SELECT CONCAT(apellido1, ' ', nombre) AS empleado
FROM empleado ORDER BY empleado;

Bonus: sin el ' ' en el medio queda todo pegado ("MagañaMarcos").

4Aumento del 20% mal calculado

ejemplo_20261005.sql (clase)
-- salario + (salario + 0.20) = el doble + 0.20
SELECT nombre, (salario + (salario + 0.20)) FROM empleados;
-- 20% más = multiplicar por 1.20
SELECT nombre, precio_venta * 1.20 AS con_aumento FROM producto;

5Falta el punto y coma entre sentencias

ejemplo_20261005.sql (clase)
SELECT * FROM pedido WHERE comentarios IS NOT NULL
SELECT * FROM pago
SELECT * FROM pedido WHERE comentarios IS NOT NULL;
SELECT * FROM pago;

6Columna ambigua en un JOIN

Parcial · ejercicio 2, punto 5
SELECT e.nombre, o.ciudad FROM empleado e
INNER JOIN oficina o ON e.codigo_oficina = o.codigo_oficina
WHERE codigo_oficina = 'MAD-ES';
SELECT e.nombre, o.ciudad FROM empleado e
INNER JOIN oficina o ON e.codigo_oficina = o.codigo_oficina
WHERE o.codigo_oficina = 'MAD-ES';

7Funciones de SQL Server y fechas mal escritas

Parcial · ejercicio 2, puntos 1, 6 y 7
SELECT COUNT(*) FROM pedido
WHERE fecha_pedido BETWEEN '01/01/2009' AND '31/01/2009';
SELECT COUNT(*) FROM pedido
WHERE fecha_pedido BETWEEN '2009-01-01' AND '2009-01-31';
